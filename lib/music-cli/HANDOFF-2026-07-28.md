What got built, what's true, and what's still open. Read this before touching
the TP-7 tooling again.

## What shipped (working, committed)

- **`music tp7 memos [dir]`** — transcribes voice memos out of the pulled pile
  into Obsidian notes in the **main vault** (`…/Documents/ejfox/voicememos/`).
  Whisper (`ggml-base.en`) classifies speech vs jam; speech gets a full
  transcript + a note. Idempotent ledger: `~/.local/share/music-cli/memos-ledger.tsv`.
  **Ran tonight: 81 memos → 81 notes in the vault.** This is done and safe.
- **`music tp7 rename-memos [--go]`** — renames memos *on the device* to readable
  `2023-12-24 dont-stay-without-a-gun.wav` names from the transcripts. Names are
  computed offline (tested/correct); on-device apply uses the `tp7` CLI. **Not yet
  run end-to-end against the device** (see blockers).
- **`music tp7 clean [--go] [--limit n]`** — deletes from the TP-7 only files
  verified in BOTH `~/tp7` and R2. Offline dry-run tested; delete now uses
  `tp7 rm`. **Not yet run end-to-end** (see blockers).
- **zsh bug fix**: `tp7_analyze_audio` used bash `${var,,}` — a hard error under
  this zsh script that had been silently breaking whisper auto-naming in
  `music tp7 pull`. Fixed to `${(L)var}`.
- **Playability sweep**: 11 zero-byte files (`01.wav`–`09.wav`, a 2018 DJ mix, a
  2018 field recording) were the "won't play" culprits — **deleted from the local
  archive**. The other 327 recordings play fine.

## Hard-won facts (do not re-learn these the hard way)

1. **The auto-watcher and the manual `tp7` CLI FIGHT over the device.** This was
   the root cause of the entire "TP-7 keeps disconnecting" saga. The launchd
   watcher (`com.ejfox.music-tp7-watch`) pounces the instant the device enters
   MTP mode and locks it via libmtp — so any manual `tp7 ls/rm/rename` gets
   "device busy / no devices found." **The device was never broken.**
   - Normal use (plug in, let it auto-pull): watcher ON — works great.
   - Manual device work (rename-memos / clean): **must pause the watcher first**,
     or it will lose every race:
     ```
     launchctl bootout   gui/$(id -u) ~/Library/LaunchAgents/com.ejfox.music-tp7-watch.plist   # pause
     # …do manual tp7 work…
     launchctl bootstrap gui/$(id -u) ~/Library/LaunchAgents/com.ejfox.music-tp7-watch.plist   # resume
     ```
2. **libmtp cannot delete on the TP-7** — `mtp-delfile` returns PTP error 2009
   "Invalid Object Handle". Its `tp7-detach-driver` also *captures* the USB
   interface and leaves a stale kernel owner (needs reboot to clear). We moved
   device mutation to the native **`tp7` CLI** (`brew install totocaster/tap/tp7`,
   github.com/totocaster/tp7) — direct USB, supports `rm`/`rename`, folders
   `/recordings /memo /library`.
3. **The `tp7` CLI's *listings* are unreliable when the device idles out** — it
   returns partial output (e.g. "73 files, /memo empty") as if complete. Do NOT
   trust a single `ls`; the device holds a manual MTP session only ~4–5 ops
   before dropping. The trustworthy full inventory came from the original libmtp
   pull in one long session (426 files).
4. **`tp7 tree` returns nothing in v0.1.0** — use `tp7 ls <path>` per folder.
5. Device modes: normal/audio (default), MTP (hold STOP while powering on),
   mass-storage (does NOT auto-mount on this Mac). Only MTP is usable for files.
